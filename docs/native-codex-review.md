# 原生 Codex 架构审查与验收

2026-11-25。当前插件为 1.3.0。目标平台为 macOS 和 Linux，Windows 为辅助平台。本机实测环境为 Apple Silicon macOS。下方耗时标注了具体版本。

## 日常任务与科研共用的能力

每个项目任务按修订保存约定、决定、已完成的动作与产物观察、待办和验收证据。普通清单可以保存在没有 Git 的文件夹，记录结束后为 `closed`，验证状态仍为 `unverified`。有客观判据的任务可声明命令和输入，验证通过后用 `finish` 完成。需要独立判断时可约定复核。项目内的归属声明依赖调用方，代码能检查证据是否过期。

原生 Codex 负责规划、执行、压缩和授权的多 Agent 协作。插件无生命周期 Hook。日常任务使用通用技能；科学假设、适用范围、参考解、误差阶和负例等方法放在可按需加载的科研技能中。技能选择由 Codex 和用户共同决定。

## 1.2 科研试用

在临时普通文件夹用左端点法与复合梯形法计算 $\int_0^1 x^2\,dx$。两种计算都能正常结束。以 $1/3$ 为解析参考，把分段数 $n$ 从 8 连续翻倍到 128。每次记录绝对误差 $E_n=|I_n-1/3|$，计算观察阶 $p_n=\log_2(E_n/E_{2n})$。二阶的事先判据为每组 $|p_n-2|\le 0.05$。左端点法的观察阶由 0.969 趋近 0.996，梯形法四次均为 2.000。这个区间和被积函数下，结果支持梯形法的二阶主张，左端点法提供负例。

试用者用同一个检查点 CLI 绑定测量脚本、记录误差表和负例，然后执行验收。程序返回通过对应的是对照实验预设的断言，包括识别出左端点法不满足二阶判据。它不认证任意函数或其他实现具有同样收敛阶。试用数据位于测试工具的临时目录。

## 核实原生压缩

官方于 11 月 24 日发布 0.172.0。该版手动压缩会依据功能配置和 provider 能力选择路径，包括无需模型请求的 TokenBudget 重置、本地压缩和远端 V2。普通本地用户文本按最近优先、约 20,000 个估算 token 的预算保留；远端 V2 客户端代码另有约 64,000 的保留预算和条目筛选。这些值是该版本的实现细节。初始化上下文会重新装配，恢复可从持久化的替换历史和后续事件重建。[版本发布](https://github.com/openai/codex/releases/tag/rust-v0.172.0) · [路径选择](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/tasks/compact.rs#L49-L88) · [本地保留](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/compact.rs#L703-L813) · [远端保留](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/compact_remote_v2.rs#L589-L658) · [恢复](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/session/rollout_reconstruction.rs#L502-L555)

Responses API 文档确认了服务端不透明的加密 compaction item。GPT-5.1-Codex-Max 系统卡明确说明该模型接受过跨上下文窗口训练。公开资料支持这些具体机制；某个当前客户端会选哪条路径、某个模型能否正确延续每个约束，需要分别检验。[Compaction 指南](https://developers.openai.com/api/docs/guides/compaction) · [模型系统卡](https://openai.com/index/gpt-5-1-codex-max-system-card/)

独立 CLI 路径此前在 macOS、Codex 0.167.1 下通过四个测试工作区的技能发现预检。该路径的登录等待未收到回调，真实模型轮次为零。可用 `python3 -B tests/probe_skill_routing.py --live` 单独复测这一入口。桌面子 Agent 的结果来自本对话的真实模型调用。

## 1.3 日常任务开关对照

2026-11-25，macOS，真实桌面 `gpt-6.2-sol`、low。两项任务均先写一份只允许透露部分安排的通知，随后改地点或时段、预算和待办。第三轮在原对话回忆，第四轮换一个无继承的新 Agent，只给项目目录和问题。每次评九项，分别核对当前四项、原约定两项、撤销事项、变更原因、实际改过的文件。仅凭目录里看见一个文件，不足以确认其修改历史。脚本、项目状态和回答分别检查。[完整原题和独立 CLI 对照入口](../tests/probe_skill_routing.py)

**缓存口径**。分子是全部调用的缓存输入之和，分母是同一批调用的全部输入之和。定稿两次首次安排加权 89.57%，修订 97.23%，原对话回忆 95.68%，新对话回忆 96.25%。首次安排的首个请求分别命中 14,720 / 23,824 和 14,720 / 23,829。两个新接手者的首个请求已命中 23,680 / 23,811 和 23,680 / 23,819。首个请求发出时还没运行本回合的检查点脚本。对应四个关闭组首请求同样有原生命中。技能清单增加的输入约 176 token，前缀匹配差异可涉及更多后续 token。这里记录观察到的差值，无法把共享服务上的每个差异归因给插件。

**长期留存的边界**。Codex 负责人对登录态 Codex / Work 的公开说明支持回到旧对话后仍能复用缓存。OpenAI 对 Codex agent loop 的说明把缓存复用限定在匹配前缀。新的问题、工具输出、不同初始化上下文或一次压缩后的请求仍需分别计量。API 的按时长缓存参数有独立的适用范围。开源仓库里也有登录态长回合之后首个请求异常低命中的使用者报告，本次试验不能解释服务端归因或配额结算。项目只靠稳定、小规模的技能描述进入发现清单，持久记录留在磁盘，需要时才读。[产品公告](https://x.com/thsottiaux/status/2112712984644784534) · [官方实现说明](https://openai.com/index/unrolling-the-codex-agent-loop/) · [API 文档](https://developers.openai.com/api/docs/guides/prompt-caching) · [带公告原文和实测记录的社区问题](https://github.com/openai/codex/issues/61757)

**长状态与程序恢复**。在同一台 Mac 连续启动 256 个真实写入进程，逐版更改预算、待办和同一通知，每版记录一次文件观察。最后的检查点为 252,860 B，256 次写入共 10.591 秒。恢复当前状态只输出 770 B，中位 40.1 ms。取第一版只输出 1,071 B，中位 39.3 ms；最近五版 4,770 B，中位 40.2 ms。每种读法启动五个独立进程，首版文件摘要与当时内容相符，读取前后状态文件字节相同。为防同一修订积累数百条日志，日常历史查询每版每类最多显示最近 8 条；截断时返回该类原总数和完整查询方式，原记录保留。单文件随输入线性积累，每次写入需要重新序列化整份状态。当前数字不是多年规模的容量保证。

系统 CLI 0.167.1、桌面附带的 0.171.0-alpha.13.2 与稳定发行版 0.172.0 均通过两次 `thread/compact/start`、重启 app-server、按线程 ID 恢复、再开全新线程的对照。已排除的约定、原行动、曾被替换的待办和旧验证都能从安装包的 CLI 查到。恢复读保持状态文件的字节和修改时间，带副作用的验证器总共只执行一次。模型回复和压缩摘要由本地夹具提供。这里验证客户端生命周期与恢复协议；线上模型的自主恢复和生产缓存以上面的真实会话另计。[原生恢复测试](../tests/test_sci_loop_native_codex.py)

## 1.3 持续 16 轮的日常项目

按长对话标准单独测试同一项书架工程。两边各有一个从头参与的真实桌面会话，逐轮推进量墙、物料、采购、限重、换班、改开放时间、印刷和交钥匙，生成同样五份业务文件。第 16 轮回忆历史。随后各开一个无继承的新会话，给同一个项目目录做同一项回忆。比较开始前固定全 16 轮和第 5–16 轮两个统计区间。短任务、额外的新对话以及索取计量 ID 的操作都在这两个区间之外。关闭组先行，开启组随后；两组均为 `gpt-6.2-sol`、low，服务器缓存可共享。未做填充、预热或失败回合剔除。[16 轮完整原题](../tests/probe_skill_routing.py)

| 区间 | 插件 | 输入 | 缓存输入 | 未缓存输入 | 输出 | 调用 | 耗时 | 加权命中率 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1–16 | 关闭 | 1,331,041 | 1,285,248 | 45,793 | 4,949 | 45 | 227.965 s | 96.56% |
| 1–16 | 开启 | 1,917,885 | 1,832,832 | 85,053 | 8,781 | 47 | 296.213 s | 95.57% |
| 5–16 | 关闭 | 937,722 | 919,808 | 17,914 | 3,346 | 30 | 135.584 s | 98.09% |
| 5–16 | 开启 | 1,409,646 | 1,367,936 | 41,710 | 6,075 | 31 | 195.604 s | 97.04% |
| 单独的新对话 | 关闭 | 122,848 | 118,912 | 3,936 | 737 | 5 | 34.970 s | 96.80% |
| 单独的新对话 | 开启 | 279,127 | 261,504 | 17,623 | 1,175 | 9 | 52.872 s | 93.69% |

开启组持续工作阶段的 12 个整轮逐个都超过 95%，最低 95.24%，最高 99.11%。全 16 轮加权超过 95%；第 1 轮为 84.76%，第 2 轮为 92.75%。原生关闭组首轮为 84.90%。两组第一个模型调用都命中 14,720 个 token，输入分别为 23,711 和 23,887。开关的高命中主要由原生 Codex 提供。开启组全程的观察值低约 0.99 个百分点，多 586,844 个输入 token，其中 39,260 个未缓存，另多 3,832 个输出、2 次调用和 68.248 秒。第 16 轮首个调用的输入，关闭为 34,699，开启为 52,962。开启组在多轮做了额外的检查点查询，随后的调用也携带更长的历史。命中率达到目标仍有实质开销，不能从订阅用量事件换算金额。

**恢复了哪些事实**。原线程均能答全，包括最初预算、改址原因、原物业待办和上午换班。两个全新线程都能从业务文件找到当前 550 元预算、26 和 23 元两次支架单价、支出 210 元、余额 340 元，以及周六物业交钥匙给小林、由小林通知阿宁。关闭组只能查到当前上午值守人为小林和板材用二留一，最初预算、改址原因和原物业待办未知。开启组另找回最初 730 元预算、南门挡推车、撤销询问消防通道宽度，以及留板是因为物业限制两层。两组都没有把钥匙待办误报为完成。

剩下一处缺口是换班的历史。用户当轮只允许更新值班表；接手者能证实小林现任，均无法证实之前是小何或是否发生替换。开启组状态最终有 6 版约定、9 条行动或决定笔记、10 条产物观察，大小 10,433 B。五个业务文件的最终内容均与各自在账本中最近一次观察的 SHA-256 相符。旧版文件内容与没有记录的决定，无法从摘要反推。普通文件夹如需保留完整版本，可用 Git；重要变更原因宜在允许保存的里程碑写下。

两条真实长会话的 92 个模型响应均与逐轮累计用量匹配，双方都未观察到自动 Compact。第 5–16 轮是持续工作窗口；它不能替代跨天缓存实验或对生产远端压缩器的评估。压缩与进程重启的机械保证由上面的原生夹具单独检验。本轮保留了 16 个短任务测试线程和 4 个长项目测试线程的原生记录。临时项目、隔离安装与工作区技能链接随测试释放。

复跑时使用 `python3 -B tests/probe_skill_routing.py --suite daily-long`，以 `--without-plugin` 选择另一臂，预检仅确认发现状态。显式加 `--live` 才调用模型。桌面线程按 `python3 -B tests/measure_turn_usage.py --date YYYY-MM-DD --turns 16 UUID` 读取全程，加 `--from-turn 5` 读取后段。计量回归覆盖旧日志、重复和跨轮响应、缺数、冲突与压缩事件。[计量回归](../tests/test_measure_turn_usage.py)

## 1.0 与 1.1 的历史开销对照

同一台 Mac、系统 Python 3.9.6、Git 2.54.0。每种路径各使用十个新建的一文件 Git 仓库，以轮换顺序执行。提交 `fixture.txt` 内容 `baseline\n`，目标为 `Exercise a minimal phase.`，命令为 `true`；开始后将文本改为 `changed\n`。整段耗时含各 Python 进程启动，表列中位数。字节数为最终 `.ai-loop` 中普通文件的逻辑字节。比较范围截至恢复，未计入独立审查；本表不用于估计 1.2 的耗时。

| 路径 | 命令 | 全程 | 最后一次恢复 | 状态文件 / 字节 |
| --- | --- | ---: | ---: | ---: |
| 原生 Codex，未启用任务检查点 | 无插件命令 | 无此项开销 | 由 Codex 恢复 | 0 / 0 |

## 使用边界与维护

- 操作笔记由执行者提交，文件指纹由 CLI 在读取产物时计算。核对指纹能确认观察时的内容，作者、操作方式和业务正确性仍需其他证据。每次检查点写入本身是原子的，业务文件改动与随后的登记是两步；若在其间退出，恢复时先核对文件或 Git，再决定是否补记、继续或重做。旧格式丢过的待办轨迹无法事后生成。

- 用户原始要求由调用方通过 UTF-8 文件或 stdin 显式提供。普通 Codex 安装没有自动截获每一条用户消息的特权。修订须提供完整的新约定并匹配预期修订号。按修订区分执行者笔记、实际验证和具名复核。理论结果可单独提交复核；有命令的任务必须通过该命令。
- Git 项目默认绑定 HEAD、索引、实际变更及声明输入。普通文件夹只对声明的文件取指纹，验证脚本本身也要显式声明。只为纯内容检查显式选用 `--tree-only`，这样仅保存检查点的提交仍可复用结果。依赖提交号或历史的命令须保留默认设置。忽略文件需显式声明，环境、网络服务、未声明的外部依赖及符号链接指向的外部数据需另行记录。协作进程锁和原子替换处理进程中断；文件系统断电恢复、网络文件系统锁语义和恶意工作区写入者不在保证范围内。
- 用前台、可重复执行的命令验证。超时和中断会尽力终止同进程组的子进程；主动脱离会话的程序可能继续运行。重新执行中断的实验前先核对已有结果。1.3 保留最新命令记录和最多 8 KiB 输出尾部，历史修订按需查询旧执行摘要和报告指纹；重要的原始实验、负例和被替换的审计报告应按项目需要归档。用户原文修订与有意义笔记按任务累积，可由 Git 归档；没有自动删除用户数据的策略。
- 源码、两个技能和测试夹具随仓库维护。升级 Codex 时先复跑发行检查、两次 Compact 和重启对照。CI 定义覆盖 macOS 与 Linux，使用官方 CLI 和回环服务。此次本机没有可用的 Linux 或 Windows 运行环境，也没有触发远程 CI。真实 Windows PowerShell 和 Linux 沙箱未在本机实测。
- 测试使用有作用域的临时目录和隔离账户目录。正式保留的是源码、测试输入及本报告；未向用户 Codex 安装插件。仓库未新增测试缓存、原始对话、发行安装包或重复日志，原有历史实验记录保留。
