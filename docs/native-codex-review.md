# 原生 Codex 架构审查与验收

2026-11-25。基线为 `1eaabdb`，优化后的插件版本为 1.1.0。目标平台是 macOS 与 Linux，Windows 为辅助平台。本轮实际执行环境为 Apple Silicon macOS。

## 职责取舍

历史上，PowerShell 工具箱承担了阶段拆解、Worker 调度和多份记忆文件维护。到 v1.0，正式插件已经采用原生 Codex 线程执行。其可靠性设计仍有价值，但普通安装暴露了六个技能和六类生命周期 Hook，严格验收依赖额外宿主为复核身份、运行环境和签名收据背书。普通 Codex 用户很难单独完成这一流程。

v1.1 默认只提供两个技能。Codex 负责规划、工具执行、压缩、续跑和授权的多 Agent 协作。插件按任务显式保存约定、决策、待办、验证记录与复核依据。普通安装不注册 Hook，不在压缩前后自动回填摘要，也不自动委派审计。高风险任务可在任务约定中声明 `--require-review`；一次真实失败或测试不足可以成为召集复核的理由。维护者保留旧状态格式及签名路径，成本是仓库继续维护两种证据协议。默认使用路径的文件数、进程数和步骤减少；总代码量因兼容逻辑和真实客户端测试增加。

## 核实原生压缩

官方于 11 月 24 日发布 0.172.0。该版手动压缩会依据功能配置和 provider 能力选择路径，包括无需模型请求的 TokenBudget 重置、本地压缩和远端 V2。普通本地用户文本按最近优先、约 20,000 个估算 token 的预算保留；远端 V2 客户端代码另有约 64,000 的保留预算和条目筛选。这些值是该版本的实现细节。初始化上下文会重新装配，恢复可从持久化的替换历史和后续事件重建。[版本发布](https://github.com/openai/codex/releases/tag/rust-v0.172.0) · [路径选择](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/tasks/compact.rs#L49-L88) · [本地保留](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/compact.rs#L703-L813) · [远端保留](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/compact_remote_v2.rs#L589-L658) · [恢复](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/core/src/session/rollout_reconstruction.rs#L502-L555)

Responses API 文档确认了服务端不透明的加密 compaction item。GPT-5.1-Codex-Max 系统卡明确说明该模型接受过跨上下文窗口训练。公开资料支持这些具体机制；某个当前客户端会选哪条路径、某个模型能否正确延续每个约束，需要分别检验。[Compaction 指南](https://developers.openai.com/api/docs/guides/compaction) · [模型系统卡](https://openai.com/index/gpt-5-1-codex-max-system-card/)

## 实际验证

| 检查 | 观察结果 |
| --- | --- |
| 原生安装 | CLI 0.167.1、桌面附带的 0.171.0-alpha.13.2 和另行校验发行物的 0.172.0 均能从本地 marketplace 安装并发现两个技能，包内 Hook 注册及调用均为零。macOS 根安装脚本在含空格的路径和重复安装下通过。 |
| 两次 Compact 和跨进程恢复 | 真实 app-server 使用本地固定 Responses 服务。对实验线程手动压缩两次，中间插入一轮，退出服务进程后按线程 ID 恢复。下一请求保留近期被截断的文本及第二份合成摘要，两版早期请求的标记均已缺失。未压缩的重启对照仍含完整原文。用实际 `command/exec` 在 workspace-write 沙箱调用安装副本，精确取回含中文、ε、CRLF 的当前修订、决定和下一步；磁盘同时保留原始约定。每版本完整对照使用 14 次回环请求。 |
| 真实性及任务控制 | 原生 CLI 回归覆盖真实数值容差、输入变化、原始与替换约定、伪完成请求、复核过期、提交身份变化、暂停/阻塞/撤销、并发写入、中断和超时。验证失败以非零退出。独立复核找出的提交号漏判、后台进程中断和输出管道阻塞均已修复并纳入测试。 |
| 高强度兼容门禁 | 以临时密钥和夹具运行签名收据、能力 ABI、显式适配器测试。修改请求、原始证据、工作区、暂存区或验证日志后旧结果失效。已验收的历史记录可凭受保护收据重查，缺少新绑定的旧证据需要重验。托管续跑有上限，暂停优先于放行。真实 LumiForge 签发体系未接入。 |

这些测试分别观察了客户端实际发送的输入、持久化的文件和命令的真实退出状态。实验提供合成摘要，恢复读取由测试显式发起。由此可以确认机械恢复的增益；线上摘要质量、模型自主选择恢复工具的概率、科学判断的正确率、Prompt Cache 命中率和实际 token 节省量均未测量。原生 Codex 即使不启用检查点也已有跨进程恢复与历史重建能力。

## 开销对照

同一台 Mac、系统 Python 3.9.6、Git 2.54.0。每种路径各使用十个新建的一文件 Git 仓库，以轮换顺序执行。提交 `fixture.txt` 内容 `baseline\n`，目标为 `Exercise a minimal phase.`，命令为 `true`；开始后将文本改为 `changed\n`。整段耗时含各 Python 进程启动，表列中位数。字节数为最终 `.ai-loop` 中普通文件的逻辑字节。比较范围截至恢复，未计入签名审计或人工判断。

| 路径 | 命令 | 全程 | 最后一次恢复 | 状态文件 / 字节 |
| --- | --- | ---: | ---: | ---: |
| 原生 Codex，未启用任务检查点 | 无插件命令 | 无此项开销 | 由 Codex 恢复 | 0 / 0 |
| v1.0 阶段 | init、start、collect、resume | 491 ms | 105 ms | 17 / 3,067 B |
| v1.1 普通检查点 | start、verify、show | 370 ms | 121 ms | 2 / 888 B |
| v1.1 兼容阶段 | init、start、collect、resume | 580 ms | 111 ms | 18 / 3,643 B |

本样本的普通路径全程缩短约 25%，恢复本身多用约 16 ms，因为它重新核对证据。兼容路径增加了测试前后的工作区比对，成本高于旧版。大型数据集的哈希读取可能主导耗时。未启用检查点的普通会话仍有两个可发现技能的描述；零注册 Hook 指的是没有额外生命周期命令。

## 使用边界与维护

- 用户原始要求由调用方通过 UTF-8 文件或 stdin 显式提供。普通 Codex 安装没有自动截获每一条用户消息的特权。修订须提供完整的新约定并匹配预期修订号。按修订区分执行者笔记、实际验证和具名复核。理论结果可单独提交复核；有命令的任务必须通过该命令。
- 默认绑定 Git HEAD、索引、实际变更及声明输入。只为纯内容检查显式选用 `--tree-only`，这样仅保存检查点的提交仍可复用结果。依赖提交号或历史的命令须保留默认设置。忽略文件需显式声明，环境、网络服务、未声明的外部依赖及符号链接指向的外部数据需另行记录。协作进程锁和原子替换处理进程中断；文件系统断电恢复、网络文件系统锁语义和恶意工作区写入者不在保证范围内。
- 用前台、可重复执行的命令验证。超时和中断会尽力终止同进程组的子进程；主动脱离会话的程序可能继续运行。重新执行中断的实验前先核对已有结果。默认只保留最新命令记录、输出摘要及最多 8 KiB 尾部；重要的原始实验、负例和被替换的审计报告应按项目需要归档。用户原文修订与有意义笔记按任务累积，可由 Git 归档；没有自动删除用户数据的策略。
- 源码、两个技能和测试夹具随仓库维护。升级 Codex 时先复跑发行检查、两次 Compact 和重启对照。CI 定义覆盖 macOS 与 Linux，使用官方 CLI 和回环服务。此次本机没有可用的 Linux 或 Windows 运行环境，也没有触发远程 CI。真实 Windows PowerShell、Linux 沙箱和生产签名宿主均不标记为实测通过。
- 测试使用有作用域的临时目录和隔离账户目录。正式保留的是源码、测试输入及本报告；未向用户 Codex 安装插件。仓库未新增测试缓存、原始对话、发行安装包或重复日志，原有历史实验记录保留。
